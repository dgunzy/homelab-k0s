## What this is

Most GPU-on-Kubernetes tutorials start with a cluster that already has a GPU node in it. This
blueprint starts one layer lower, where GPU platforms actually start: **bare-metal hosts that
run virtual machines**, with GPUs passed through to the VMs that need them, and Kubernetes
clusters whose nodes are created, replaced and upgraded through an API.

Everything is declarative and pinned, and the repository is the source of truth. The reference
deployment runs on a single desktop with one consumer GPU; nothing in the design depends on that.
